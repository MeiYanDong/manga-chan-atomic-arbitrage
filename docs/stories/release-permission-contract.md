# Story: 限制性发布环境不能破坏服务身份隔离

## 用户结果

作为经营者，我希望同一不可变发布包能被签名器、只读经营面板和竞争雷达各自的隔离身份正常加载，
而不依赖发布人员记得执行一次人工权限修复。

## 验收标准

- 在调用方 `umask 0077` 下安装，发布目录及运行依赖仍可由 `manga-board` 读取和遍历；
- 组用户和其他用户不能修改不可变发布代码；
- 私钥、RPC 配置、Webhook、凭据目录和交易状态继续使用显式的最小权限；
- 安装过程不启动、不授权、不签名、不广播；
- CI 对权限策略的顺序建立回归断言；
- 生产读回以真实的隔离用户依赖导入和服务健康状态为准，不能只看 root 构建成功。
