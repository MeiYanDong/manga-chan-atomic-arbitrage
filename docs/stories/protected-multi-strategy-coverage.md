# Story：忙碌市场不能饿死另一条策略或周期恢复

## 用户结果

作为实盘经营者，我希望 Earn、Global 和普通池子机会都持续获得检查；某个平台事件很多时，程序仍会按时恢复扫描漏掉的
日志、新池和长尾路线，而不是看起来在线却只服务最吵的一条队列。

## 验收标准

- Earn 与 Global 有独立且不可被事件重置的周期截止时间；
- 已到期恢复任务先于普通事件和面板候选；
- 多条事件仍按池与资产并集合并，不因公平调度重新引入覆盖丢失；
- Global 的节流不阻止 Earn，Earn 事件也不能无限推迟 Global 恢复；
- 公开状态能看到每条 lane 的运行次数、待处理类型和最大迟到；
- 所有执行继续通过唯一 signer/nonce lane 以及原有授权、利润、Gas、模拟、余额和回执门禁。

## 非目标

- 本故事不把同步 Global 子进程改为常驻 worker；
- 不承诺固定毫秒延迟、成交次数或收益；
- 不改变本金和风险预算，不新增钱包或并行 signer。
