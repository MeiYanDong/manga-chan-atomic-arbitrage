# Story: 搜索不再堵住唯一签名通道

## 用户结果

作为经营者，我希望 Earn 与全局跨协议机会持续并行搜索，而唯一签名通道只处理最新状态下确实可能成交
的候选，避免一次慢扫描让另一条路线错过窗口。

## 验收标准

- Earn 和 Global 的事件搜索、周期恢复都先进入各自的常驻只读工作进程；
- 两个工作进程只接收白名单环境，不含签名凭证、托管 RPC/WSS、Webhook 或 live arm；
- 忙时信号按池、资产和序列合并，不丢依赖；
- 只有 15 秒内且证据完整的负结果可以跳过重复搜索；
- Global 正候选不携带可直接执行的 plan，签名端必须从相同图承诺重新定位路径并重建；
- 签名前再次验证当前资金、最新报价、Gas、净利润、模拟、余额、nonce 与授权；
- 工作进程失败只降级对应适配器，不停止另一条搜索路线；
- 面板只展示工作进程是否运行、是否正在搜索、排队、完成、失败、重启和合并数量；
- 测试覆盖环境白名单、协议边界、信号合并、负结果新鲜度、正候选篡改、stdin 大小与执行入口。
