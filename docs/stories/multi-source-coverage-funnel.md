# Story: turn source coverage into a truthful live opportunity funnel

## Outcome

As the strategy owner, I want every independently discovered multi-pool target to enter a bounded quote graph and I
want the dashboard to show where candidates are filtered out, so a large pool count cannot be confused with current
profit or with complete market coverage.

## Acceptance criteria

- PAIR, LONG and Doppler target identities are joined to canonical PoolManager pool facts without changing their source
  attribution.
- A source target enters the board only when at least two canonical non-native V4 pools survive normalization.
- No target carries more than eight source-graph pools unless preserving a larger pre-existing PAIR API set requires it.
- An arbitrary chain-attested hook may be quoted by the read-only board but cannot become executor-compatible.
- A current-executor-shaped pool with unknown API depth needs a successful requested-size fixed-block quote before it
  can become executor-compatible for that observation.
- One periodic candidate completes without event preemption; event polling and bounded event wakes continue.
- The overview separately displays discovered pools, multi-pool targets, admitted candidates, fresh results,
  proxy-positive screens and exact-preflight-ready routes.
- The primary Chinese copy says coverage is limited whenever fresh results cover only part of the admitted graph.
- Tests assert graph bounds, source attribution, unsupported-hook isolation, protected scheduling and funnel semantics.

## Risk boundary

- The board remains loopback-only, signer-free and unable to broadcast.
- The active dual signer, authorization ID, capital limits, exact net floor, failed-Gas breaker and
  contract bytecode are unchanged.
- Unknown-hook live execution and a universal V4 executor are explicitly out of scope.
