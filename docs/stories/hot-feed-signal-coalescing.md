# Story：高频 Feed 不能放大为实盘内存故障

## 用户结果

作为实盘经营者，我希望事件入口即使每秒收到几十个重叠或相关帧，程序也能持续运行并保留所有必要池/资产依赖，
而不是因为内部展示文字不断自我拼接而退出。

## 验收标准

- 20,000 次交替原因合并后仍只有两个原子原因；
- 展示原因只由原子原因派生，长度不随重复帧增长；
- sequence 范围、消息数、池与资产依赖仍按并集保留；
- 原因长度、原因数量、信号值数量和 WebSocket frame 都有显式硬上限；
- 超大 frame 不进入字符串转换或 JSON 解析，Feed 降级后公共日志与周期恢复继续；
- 修复不改变资金上限、利润门槛、Gas、nonce、模拟、签名、提交或回执规则；
- 生产验收必须读取持续运行内存、服务重启、Feed 计数、授权、nonce、余额和未决交易。

## 非目标

- 不把 Feed 命中当成可执行机会或收益；
- 不因这一缺陷增加堆上限或服务器规格；
- 不在本故事内完成所有协议的常驻 canonical state 与独立 Feed relay。
