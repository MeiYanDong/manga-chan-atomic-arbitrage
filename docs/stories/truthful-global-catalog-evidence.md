# Story：全局搜索不再把证据缺失说成没有机会

## Outcome

作为实盘经营者，我希望看到的“没有机会”“没有可执行资金”和“数据没有读全”是三个不同结论，并且每一轮
新的多池覆盖都真正获得容量，而不是被上一轮缓存悄悄挤掉。

## Acceptance criteria

- 基础目录刷新只查询 Earn 资产与 USDG/WETH 的 V2/V3 连接，不接收轮换市场资产或轮换 V4 池；
- 当前 `global-universe.json` 只在内存合并，完全重复的旧缓存 PoolKey 只计一次且整组仍显示已接入；
- V2/V3 请求数、传输失败数和完整性具有结构校验，错误文本不得保留 RPC 地址或凭据；
- 完整或部分目录最多读取六小时，唯一 writer 是独立无凭据维护服务，搜索与签名子进程都不获得写权限；
- 目录不完整且没有正向结果时，状态不能是完整证据的 `NO_EXACT_NET_OPPORTUNITY`；
- 没有 Morpho 或受保护执行器库存时，分类为资金策略过滤，不伪装成 RPC 故障；
- 经营 API 只展示完整/部分、请求规模和失败计数，不展示 provider、原始调用或原生错误；
- 单元测试覆盖旧轮次重复池、部分传输、凭据脱敏、缓存重试、资金缺失和负向分类；
- 实盘部署后必须读回当前轮的 selected/admitted 覆盖、目录证据、工作集与无未决交易；
- 没有 canonical receipt 时不得新增收益记录。

## Non-goals

- 不自动移动其他执行器或钱包的资金；
- 不降低净利润、Gas、nonce、模拟、授权或回执门槛；
- 不把更多候选池等同于更多可实现利润；
- 不声称解决排序流竞争、私有订单流或同区块反事实归因。
