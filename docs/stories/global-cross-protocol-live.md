# 全局跨协议原子套利故事卡

## Story 1：统一机会图，不再按代币名称写路径

作为策略经营者，我希望 Earn 与 Uniswap v2/v3/v4 的合法流动性边进入同一资产图，让任意结算资产闭环都能
被发现，而不是每发现一个 AI、meme 或股票代币再加固定路线。

验收：

- 图同时包含四个场所和 Earn 加/退流动性超边；
- USDG、WETH 均能发现跨场所闭环；
- 当前 Earn 资产自动查询 v2/v3，v4 来源必须有审核或链上目录证明；
- Factory 返回的 V2/V3 池必须分别有非零储备/active liquidity，空池只进入隔离证据；
- Earn 输入边按代币对 canonical Permit2 的固定区块调用能力 admission，不影响该代币的其他协议边；
- 2～4 跳枚举有组合上限、事件优先级与轮转覆盖，未入本轮不等于永久过滤。

## Story 2：通用执行但不能任意调用

作为钱包所有者，我希望一笔交易能组合多个协议，同时任何发现数据都不能把执行器变成任意授权代理。

验收：

- 合约只支持六种 typed action，未知动作、伪池、错误 callback 和残余资产全部回滚；
- Morpho 闪电贷与库存模式分别验证本金偿还和库存基线；
- v2、v3、v4、Earn Swap、Earn 加池、Earn 退池都有确定性正向和负向测试；
- 真实协议 fork 分别用可兼容的 ETHUSD 池验证加/退池，不把 EARN 的 Permit2 限制伪装成执行器能力；
- `quoteWithFlash`、模拟和失败交易不计作收益。

## Story 3：发现后走最短可信提交路径

作为实时套利者，我希望相关池更新立刻唤醒精确检查，并优先向 Sequencer 发送已经落盘的唯一签名原文。

验收：

- Feed 断线自动重连，动态地址集合有 1,024 个上限且不持久化原始消息；
- 相关池至少命中一个即可唤醒，其余候选由区块轮转获得覆盖；
- 受控 RPC 只接收公共阶段毛利正的候选，每条路线保留一个金额且每轮最多 16 个；
- 直连 Sequencer 失败时只允许广播同一 raw transaction；
- nonce、raw、receipt、事件和余额效果可在崩溃后重放核对。

## Story 4：实盘证据进入经营面板

作为经营者，我希望面板只展示可读的执行结论，不把内部 calldata、原生字段或模拟利润冒充经营结果。

验收：

- 全局执行计数和 USDG 归一化净利润只来自 receipt-confirmed effect；
- USDG/WETH/其他结算资产保留原生金额和精度；
- 面板可区分 watcher 运行、Feed 连接、发现候选和主网已确认执行；
- 没有成交时显示零笔确认，而不是声称零机会或负收益。
