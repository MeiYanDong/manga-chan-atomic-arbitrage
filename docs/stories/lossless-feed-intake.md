# Story：连续市场事件不能相互覆盖

## 用户结果

作为实盘经营者，我希望多个池子在同一调度窗口连续变化时，每个受影响的局部路线都进入下一轮精确检查，而不是
只检查最后到达的事件。

## 验收标准

- 重叠 Feed frame 逐 message 去重，新 message 不因旧前缀被丢弃；
- 完全重复的 frame 不重复触发报价；
- gap、乱序、重复和重叠都有可读计数，且不会被描述成收益或可执行机会；
- 连续 Earn/Global Feed 事件按 pool 与 asset 并集排队；
- 一秒公开 Earn 日志和 Feed 同时到达时保留所有命中的事件池；
- 最早源时间用于排队延迟，最后到达时间保留作审计；
- 子流程仍需通过最新状态的精确报价、模拟、Gas、正净利润、nonce、余额、授权和回执门禁；
- 发布不得重配 Base 独立 signer，也不得并行创建第二个 Robinhood signer。

## 非目标

- 本故事不声称解决 Feed 服务端 403、网络 SLA 或交易排序竞争；
- 不在这一变更中重写协议 adapter、合约、资金模型或签名器；
- 不把周期扫描的“未发现”写成零机会，也不把 Feed 命中写成已盈利。
