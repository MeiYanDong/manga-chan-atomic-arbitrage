# Story：实盘存活恢复与最少必要提醒

作为实盘经营者，我希望一次无签名的慢查询不会永久停止全部策略，并只在实盘能力真正丧失或恢复时收到飞书
提醒，从而既不错过长期停机，也不会被正常的无机会和短暂波动打扰。

## 验收标准

- Global 或 Earn 子进程达到 60 秒时限且没有未决 mutation 时，本轮停止、主 watcher 继续，另一通道仍有机会运行；
- 任何未决 mutation、nonce 冲突或关键身份/合约不变量仍 fail closed，不能自动重启；
- 临时 RPC 终止由 systemd 恢复，关键安全退出不会自动恢复；
- 授权仍开启但进程死亡、运行心跳失联或通道连续三次故障时只发送一次关键提醒；
- 故障恢复后只发送一次恢复提醒；
- 无机会、毛利不足以覆盖 Gas、候选被过滤和一次 RPC/timeout 不发送提醒；
- 通知 unit 只有只读运行状态和独立飞书凭据，没有私钥、RPC 或交易权限；
- 本地质量门、GitHub quality、Linux unit 验证、生产 reconcile、飞书 code `0` 和 watcher 当前读回全部有证据。
