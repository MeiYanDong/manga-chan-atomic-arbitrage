# Earn 机会空间、漏失复盘与第一性原理路线图

- 日期：2026-09-14（Asia/Shanghai）
- 结论：AI/MOO 只是一次成交路径，不是策略定义。套利对象应是“同一状态下可原子闭合且扣除全部成本后资产
  增加”的任意可执行图。
- 证据边界：历史 receipt 证明 Earn Omnipool 套利曾可成交；结构路径、APR 或竞争者交易不自动证明当前可赚。

## 1. 多池套利的本质

把代币视为节点、可执行 swap 视为有方向且随金额变化的边。对结算资产 `A`，候选路径为：

```text
A -> venue/pool 1 -> token B -> ... -> venue/pool n -> A
```

只有同一区块精确报价满足下式，才进入最终预检：

```text
final A - initial A - worst-case Gas - safety margin > minimum net profit
```

利润来自独立池之间不一致的边际兑换率。交易把高估一侧卖掉、低估一侧买回，价差由旧状态的 LP 库存承担；
AI、MOO、股票或 meme 只是图上的资产标签。原子性消除中间币库存敞口，不消除失败 Gas、状态抢跑、排序、合约、
代币、管理员、RPC 与密钥风险，所以不能称为数学意义的无风险。

最优金额也不是“把钱包全打进去”。随着金额增加，滑点让边际收益下降；理论最优点是新增一单位本金带来的边际
毛利刚好等于新增滑点、费率、Gas 与保护余量。实盘用全余额范围的粗到细 exact quote 搜索这个点。

## 2. 为什么最初漏掉

1. **把例子当成本体**：首个成功 receipt 是 `WETH -> MOO -> AI -> WETH`，工程上随后把 AI/MOO 与三个池写成
   allowlist，成功样本反而形成锚定。
2. **研究与执行不对称**：研究器能枚举更多池，生产执行器只认四条路线；“研究看见”并不等于“系统会唤醒、
   会报价、会签名”。
3. **触发器继承了同一个盲区**：只监听已知三个池，未知池发生交易时连重新计算的机会都没有。
4. **竞争度量自证循环**：竞争扫描器只识别我们的已知路径，于是未知路径的机器人交易被过滤掉，错误强化了
   “外面也没有机会”的判断。
5. **过早优化错误的全集**：先优化报价次数和 Gas，再审问“机会全集如何定义”，于是把有限资源高效地用在了
   一个错误的小宇宙里。
6. **把网页索引当协议依赖**：v0.13.0 首次生产启动又被 Cloudflare 403 阻断；这次没有漏报价，而是数据平面
   错层让整个执行器停机。

## 3. 防止下次再漏

经营面板与告警应固定展示一条不能合并的 coverage funnel：

```text
Factory/Venue 已发现池
  -> 图中的边与闭环
  -> 本地入围
  -> fixed-block exact quote
  -> 毛利为正
  -> 扣 Gas 后为正
  -> 最终预检
  -> 已签名
  -> receipt 净利润
```

并建立四条持续不变量：

- 新池/未知代币测试：明天增加一个从未见过的 token，系统无需改代码即可发现；
- `research discoveries ⊆ executable policy or explicit unsupported queue`，不能无声丢弃；
- 任何竞争者 receipt 出现系统图外的闭环，立即形成 P0 覆盖缺口，而不是归类成“无机会”；
- 平台、协议、池、资产、结算资产、执行器能力分别建模，产品名称与代币叙事不能充当准入条件。

## 4. Earn 内部可正收益玩法分层

| 方向                      | 收益来源                             | 当前判断                                       | 风险/缺口                                                 | 优先级     |
| ------------------------- | ------------------------------------ | ---------------------------------------------- | --------------------------------------------------------- | ---------- |
| Omnipool 内部 2～4 跳闭环 | 不同加权池的边际价格不一致           | 已有历史净盈利 receipt；v0.13.1 改为链上全池图 | 竞争、薄深度、失败 Gas                                    | P0，已实盘 |
| Omnipool ↔ Uniswap v3/v4  | 两类 AMM 对同资产定价不同            | 已观察到外部机器人原子交易形态                 | 当前 BatchRouter 不能跨协议，需要新执行器与 venue adapter | P1         |
| 用户 swap 后 backrun      | 大额交易把单池推离其他池             | 是同一套利的更快触发形态                       | Robinhood FCFS，公共 RPC 延迟会丢排序                     | P1         |
| 新池初始定价纠偏          | 创建者用初始数量直接设价             | 结构上成立、可能出现大价差                     | permissionless 恶意 token、尘埃池、极短窗口               | P1         |

## 5. 当前实盘与下一阶段边界

v0.13.1 当前能执行：官方 Factory 加明确历史池中的任意 WETH 结算、2～4 跳、单闭环 Omnipool 路径；全图
本地粗排，公共 exact quote 最多 120，只有公共净正才进入最多 9 次受控复核，最终仍有 minOut、Gas、nonce、
余额、call 与 receipt 门禁。

尚未覆盖：非 WETH 结算但可用库存/闪电流动性闭合的路径、一次交易组合多个闭环、Omnipool 与 Uniswap
v3/v4/Rialto 之间的跨协议边、闪电贷、JIT LP 与清算。下一阶段应先实现跨协议单闭环图和通用原子执行器，因为
已有外部 receipt 证明该竞争形态存在；再根据自然机会与 receipt 净收益决定是否升级 sequencer feed 与付费 RPC。

## 6. 当前可核验证据

- Earn 官方文档：Omnipool 为 2～8 资产加权池、每次 swap 费率 0.30%，初始数量决定价格；AUTO 是由 Steer
  管理的 Uniswap 集中流动性，APR 可变而非保证。
- 官方合约目录给出 Vault、BatchRouter 与 Omnipool Factory；Balancer v3 上游 Factory 提供 `getPools()`，
  WeightedPool 暴露不可变 token/权重和当前动态余额/状态。
- 2026-09-14 链上固定区块读到当前 Factory 30 池，另有 1 个官方应用仍列出的明确历史池；31 池共形成
  7,586 条 WETH 简单闭环：两跳 134、三跳 1,070、四跳 6,382。结构数不等于可盈利数。
- 本项目此前的竞争报告在 24 小时样本中识别出外部 Earn 闭环，并观察到一笔 Earn + Uniswap v3 原子路径；
  这证明跨协议形态被竞争者使用，不证明我们当下能复制利润。
