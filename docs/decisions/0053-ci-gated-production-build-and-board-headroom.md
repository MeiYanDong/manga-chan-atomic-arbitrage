# ADR 0053：完整测试留在 CI，生产机只重建发布产物

- 状态：Accepted
- 日期：2026-09-13

## 背景

提交 `774c6865` 已在本地和 GitHub `quality` 门禁通过 272 个单元测试、3 套确定性合约测试与秘密扫描。相同测试在 2 GB 生产机重复执行时占用可用内存并使 Nginx 长时间无法响应；受控看板重启还证明增长后的紧凑来源索引会耗尽原有 256 MiB V8 堆。

## 决策

1. `npm run check` 继续作为 PR 与 main 的强制质量门禁，不降低测试范围；
2. `install-release.sh` 要求操作者先保存对应不可变提交的成功 CI 回执，生产机只运行 `release:build`；
3. `release:build` 重做类型检查、前端产物、合约产物与秘密扫描，不重复单元和确定性合约测试；
4. 看板调整为 320 MiB V8 堆、512 MiB `MemoryHigh`、576 MiB `MemoryMax`；
5. 发布后仍必须核对 loopback health、进程 release、公开 API、内存峰值和签名 watcher PID 未变化。

## 影响

- 合并前质量门禁不变，生产停机面显著缩小；
- 生产安装器本身不能证明 GitHub CI 成功，因此 CI URL 仍是发布证据中的必填项；
- 内存上限不是无限放宽。若紧凑索引再次接近 512 MiB，应优先优化投影与启动路径，而不是继续加大堆；
- 这项变更不修改钱包、授权、nonce、执行合约、Gas 门槛或广播路径。
