# ADR 0068：共享协议根不能兼任具体池

- 状态：Accepted
- 日期：2026-09-14
- 补充：ADR 0067

## 生产反馈

v0.15.1 已把原始 Feed 匹配投影成路线依赖。第一轮生产验收中，事件从 12,091 条总路线缩小到 739 条相关
路线、16 条实际报价路线，证明 WETH/USDG 的全图污染已经消失；但后续一次只有一个地址的
`SPECIFIC_POOL_OR_HOOK_MATCH` 仍触达 1,847 条路线。该轮耗时 8.621 秒，并在此期间合并了大量新信号。

根因是 Uniswap v4 目录的每条池记录都把同一个 PoolManager 写在 `address` 字段。构建 Feed 策略时，该地址
既进入“协议根”集合，也进入“具体池”集合；分类阶段因后者而把所有 PoolManager 调用误判为单池事件。

## 决策

1. 先建立完整协议根集合，再从具体池/hook 集合中删除与协议根重叠的地址。适配器字段名不能覆盖这个
   语义边界。
2. 协议根仍留在 Feed 监控集合，用于与非结算资产共同构成路径证据；它单独出现或只与 WETH/USDG 出现时
   继续过滤。
3. 独立 v2/v3 池地址、Earn 池地址和非零 v4 hook 仍可作为具体路线依赖。
4. 策略常量升级到 `SPECIFIC_POOL_OR_NON_HUB_ASSET_PATH_V3`。现有授权因承诺值不一致而自动失效；生产必须
   在无未决交易、nonce 收敛后撤销并重新签发授权。

## 不变边界

- 五分钟周期恢复仍轮转全图，不因事件过滤而失去长期覆盖；
- 不改变单轮路线数、报价金额、资金、Gas、净利润、模拟、nonce、回执和失败 Gas 约束；
- 生产没有同区块反事实时，不能把过滤信号或竞争者成交归因为我方漏单。

## 验收

- 当 PoolManager 同时出现在协议根和目录池地址时，只保留协议根身份；
- `PoolManager`、`PoolManager + WETH` 都不触发事件报价；
- `PoolManager + 非结算资产` 仍按该资产选择相关路线；
- v2/v3/Earn 独立池和 v4 hook 的精确匹配行为不变；
- 发布后公网漏斗、当前授权、服务重启数、未决交易和失败 Gas 均有生产读回。
