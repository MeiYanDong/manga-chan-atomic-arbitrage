# ADR 0069：所有结算资产共享一份事件路线预算

- 状态：Accepted
- 日期：2026-09-14
- 补充：ADR 0067、ADR 0068

## 生产反馈

授权字段 `maximumEventRoutesPerWake=8` 与 ADR 0067 都表达“一次事件最多八条路线”，但 v0.15.2 生产读回
仍显示 `selectedRoutes=16`。根因是 USDG 与 WETH 分别调用一次路线选择器，各自取得八条，然后才合并统计。
一次事件因此最多发出约两倍的粗筛报价，最近事件从 Feed 接收到结论仍需约 8.2～8.4 秒。

这不是链上资金或签名越权：单笔交易、Gas、nonce、净利润、回执和失败 Gas 门槛都没有变化。但它违背了
授权字段的直观含义，扩大公共 RPC 工作量并降低抢单时效。

## 决策

1. 先为每个结算资产生成按相关性排序的候选路线，再用一个全局八路线预算做确定性轮询分配。
2. 每轮依次给各非空结算通道一个名额，直到预算用完；某通道没有候选时，其余名额自动让给其他通道。
3. 只有事件唤醒使用共享预算。启动和五分钟周期恢复保留每通道独立的较宽轮转，以维持完整覆盖。
4. 路线工作集策略升级为 `SPECIFIC_EVENT_GLOBAL_BUDGET_THEN_PERIODIC_ROTATION_V3`，旧授权在新代码下因承诺
   不一致而失效，必须按撤销、收敛、重新授权流程发布。

## 不变边界

- 不减少结算资产种类，也不固定偏向 USDG 或 WETH；
- 不减少单条路线的动态金额范围或正毛利后的精细化报价；
- 不调整资金上限、最低净利润、Gas 缓冲、失败 Gas 熔断、模拟、nonce、签名、提交或回执规则；
- 没有报价的路线仍只代表本事件轮未入选，不代表没有机会，周期恢复继续提供长期覆盖。

## 验收

- USDG 与 WETH 各至少有八条候选时，事件实际路线数为 `4 + 4 = 8`；
- 一个通道为空、另一个通道至少八条时，实际路线数为 `0 + 8 = 8`；
- 所有事件通道合计永不超过授权的八条；
- 恢复轮的原有路线数量和轮转行为不变；
- 生产读回同时记录总路线、相关路线、实际路线、耗时、Feed 状态、失败 Gas 和未决交易。
