# ADR 0058：Earn 实盘从 AI/MOO 固定路径升级为动态 Omnipool 闭环图

- 状态：Accepted
- 日期：2026-09-14

## 背景

研究脚本已经能枚举较广的 Earn 多池路径，但生产执行器仍只允许四条 AI/MOO 路线，事件监听也只关注三个池。
因此研究层可以看见新路径，实盘层却既不会被其事件唤醒，也不能把它送入签名前复核。这是机会全集定义错误，
不是 Gas 或本金不足造成的。

## 决策

1. 官方 Omnipool API 只作为发现索引；不把名称、TVL 或 API 报价当成签名证据。
2. 每次公共预检读取全部当前已初始化目录池，枚举所有以 WETH 结算、2～4 跳、不重复池和中间代币的简单闭环。
   AI、MOO、股票、meme 或其他标签均不参与准入判断。
3. 全图只做本地加权池近似和 Gas 代理排序。最多保留 24 条路径，固定保留低 Gas 两跳路径、各跳数代表路径，
   并优先覆盖触发本次事件的池。
4. 每条入围路径最多取得三个公共 fixed-block exact quote；最多八条路径再取得六个局部细化报价。公共 exact
   quote 上限为 120。
5. 只有公共阶段在完整 Gas 缓冲后仍为正，才把唯一赢家及其金额邻域交给受控 RPC；受控阶段最多九次 exact
   quote，随后仍执行最新区块 quote、call、Gas、余额、nonce 和最小输出复核。
6. 任意 canonical Vault Swap 都可唤醒预检。动态路线必须在当前目录仍存在、池边界与链上完整 token 集一致，
   并被冻结到 mutation plan；回执必须复原完全相同的逐跳金额链。
7. 升级 authorization policy 到 v5，承诺动态池范围、最大跳数、筛选算法和两级报价上限；切换生产前必须撤销
   v4、完成 reconcile 并重新 arm。
8. 无签名的竞争回执服务同时升级为识别任意连续、逐段金额衔接的 Vault 闭环。非 WETH 结算只展示事实，不伪装
   成 ETH 收益。

## 为什么只枚举简单闭环

重复节点的闭合路径可以分解为更小闭环；先找简单闭环可避免组合爆炸，并覆盖当前单路径 BatchRouter 的直接
可执行边界。一次交易内组合多个闭环、非 WETH 库存闭环、跨协议边和闪电流动性属于下一阶段，不冒充本版本已
覆盖。

## 影响

- 新池和新代币无需改代码即可进入发现全集；
- 路径数增长不会线性消耗付费 RPC，公共调用有不可变上限；
- 任一目录或链上身份异常只会拒绝对应候选，签名前仍 fail closed；
- 事件触发面变宽，公共 RPC 用量会上升，但受控 RPC 仍只在公共净正候选出现后使用；
- v4 授权不能静默改变含义，必须显式完成 v5 切换。

## 非目标

- 不声称覆盖 Earn 与 Uniswap v3/v4、Rialto、AUTO 或其他协议之间的跨协议闭环；
- 不把 LP APR、质押奖励、杠杆循环或清算收益称为无风险套利；
- 不发送亏损探针，不因扩大池范围而取消 Gas、余额、最小输出、nonce 或回执门禁。
