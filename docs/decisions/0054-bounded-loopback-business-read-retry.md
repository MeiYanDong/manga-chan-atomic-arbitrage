# ADR 0054：经营快照对繁忙的本机看板做一次有界重试

- 状态：Accepted
- 日期：2026-09-13

## 背景

生产看板在周期性维护 4,000 余个候选时，Node 事件循环会出现超过 5 秒的繁忙窗口。经营报表恰好在这个窗口读取
`/healthz`、`/api/v1/overview` 或 `/api/v1/sources` 时，会诚实地把市场部分写成 `UNKNOWN`；但执行服务、持久化
和 Nginx 缓存仍健康。这个瞬时取数失败会被公开快照保留五分钟，让用户误以为市场服务已经停止。

## 决策

1. 报表读取仍只允许 `127.0.0.1`、`::1` 或 `localhost`，不新增公网或付费 RPC 请求；
2. 每个看板 GET 最多尝试两次，每次超时 8 秒，两次之间等待 500 毫秒；
3. 首次成功立即返回，不做额外请求；两次都失败、HTTP 非成功或 JSON 无效时仍返回 null，让经营快照保持
   `UNKNOWN`；
4. 不复用上一次市场数值，因为没有独立 `observedAt` 的旧值会在新快照中伪装成当前数据；
5. systemd oneshot 的 45 秒上限不变，三个看板请求并行执行，因此重试预算仍有界。

## 影响

- 一次看板繁忙窗口不再轻易变成持续五分钟的错误运营信号；
- 真正持续不可用时仍失败关闭，不把缓存值冒充实时值；
- 这项变更不修改报价、RPC、机会门槛、钱包、签名、nonce、Gas 或广播路径。
