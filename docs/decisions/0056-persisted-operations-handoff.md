# ADR 0056：经营报表通过原子文件读取市场摘要

- 状态：Accepted
- 日期：2026-09-13

## 背景

经营报表原先并行请求看板进程的 `/healthz`、`/api/v1/overview` 和 `/api/v1/sources`。第一次修复允许每个请求在
8 秒超时后重试一次，能够跨过普通繁忙窗口；但 2026-09-13 生产回读证明，一次较长的周期维护仍可能连续占用事件
循环超过 16 秒。此时看板和执行器实际运行正常，五分钟经营快照却会把整个市场区域写成 `UNKNOWN`。

## 决策

1. 看板每次完整发布后，同时原子写入一个不超过 64 KiB 的 `operations-snapshot.json`；
2. 文件只允许包含生成时间、健康结论、候选/报价漏斗计数和四类来源计数，不包含池明细、RPC、配置或签名字段；
3. 经营报表优先读取该文件，并要求它是普通文件、不可被组或其他用户写入、生成时间不超过三分钟；
4. 即使文件新鲜，只有 `manga-opportunity-board.service` 仍在运行时才能报告 `HEALTHY`；文件时间作为
   `market.observedAt` 保留，不能伪装成报表生成时刻；
5. 文件缺失、过期或校验失败时，保留原有的两次 loopback HTTP 读取作为迁移与故障回退；
6. 摘要发布失败不能阻止执行 feed 或市场扫描，报表会在文件过期后按原规则失败关闭。

## 影响

- 五分钟经营刷新不再与重型扫描争抢同一个 Node 事件循环；
- 看板停机、文件过期或权限异常仍不会被显示为实时健康；
- 这是只读数据交接，不修改候选选择、报价、Gas、资金、授权、私钥、nonce、签名或广播。
