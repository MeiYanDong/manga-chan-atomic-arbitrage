# ADR 0070：同场所闭环与动态结算资产准入

- 状态：Accepted
- 日期：2026-09-14
- 补充：ADR 0058、ADR 0060、ADR 0067、ADR 0069
- 授权策略：`dual-base-loopback-escalation-v11`

## 问题

历史竞争者在四笔连续交易中完成了全 Earn 闭环：

```text
PLTR --OMNI--> EARN --GLDN--> SPCX --WEAPONS--> PLTR
```

旧图已经包含三个池和六条有向边，但发现器与计划构造器都额外要求至少两个 venue。该条件不是套利成立的
经济条件，只是早期“跨协议执行器”范围被错误固化成机会定义。因此路线被软件主动排除，并非池子不存在、
资金不足或 Gas 后不盈利。

旧结算配置还有第二个边界：USDG、WETH 和手工增加的地址被当成完整 allowlist。即使任意图资产具有闭环、
可用闪电流动性和可兑现价值，也不会成为本金与利润的结算单位。这与“资产名称和平台都不应成为策略前提”
相冲突。

## 第一性原理

原子套利成立只需要以下事实同时为真：

1. 同一笔交易从结算资产出发并回到同一结算资产；
2. 每一步调用的是执行器支持且已验证身份的池，路径连续并且不重复池或中间资产；
3. 本金可由零费 Morpho 闪电流动性或受保护执行器库存提供；
4. 当前区块的精确模拟证明毛利可覆盖最坏 Gas 与最低净利润；
5. nonce、余额、deadline、残余资产和回执效果全部一致。

场所数量、代币符号、股票/meme/AI 分类都不在上述必要条件中。

## 决策

1. 统一枚举器接受两到四跳的同场所或跨场所简单闭环。发现阶段和计划阶段各自验证闭合、连续、不同池、
   中间资产不重复和动作类型；任何一层都不能只信任上一层输出。
2. USDG、WETH 与 `GLOBAL_EXTRA_SETTLEMENT_ASSETS` 改为优先种子，不再是完整 allowlist。其他资产必须先存在于
   固定区块统一图，并至少连接两个不同池，才进入候选。
3. 每个候选必须在同一固定区块验证 ERC-20 decimals、Morpho 余额、执行器库存，以及图中已确认存在的
   Uniswap v3 WETH/结算资产/USDG 可执行估值路径。缺任一项即拒绝，不能以代币名称或离线价格补全。
4. 事件轮只检查种子和事件触达资产；启动/五分钟恢复轮按区块号轮转其余候选。每轮最多做 64 个资金检查、
   最多准入 16 个结算资产，再共同分享既有路线和受控 RPC 预算。这些是计算与 RPC 覆盖上限，不是本金或
   盈利次数上限。
5. 估值探测只报价统一图已经证明存在的 v3 费率路径，不再对每个候选盲试全部费率组合。历史回执在没有保存
   图对象时可以使用原有有限费率集合做非延迟关键的核对。
6. 授权升级为 v11，并承诺图策略、同/跨场所路线策略、动态准入策略、种子和两个准入上限。v10、v9、v8
   在新代码下全部 fail closed；生产必须先撤销旧授权、停止单写者、完成 reconciliation，再重新授权。
7. 合约动作集、部署字节码和执行边界没有变化。现有 Universal Executor 已能执行该三池 Earn 计划，因此
   不为了修复 offchain 过滤错误再部署合约。

## 防止再次漏失

- 历史 PLTR 路线以真实池和代币地址作为测试 fixture；删除全部 symbol 后仍必须被发现。
- 单独测试同 Earn 三池闭环能构造成一份连续原子计划。
- 单独测试重复池、重复中间资产、非闭合终点仍被计划层拒绝。
- 单独测试非 WETH 结算资产的 Earn 路径验证、动态轮转、事件触达优先级、资金能力与 v3 估值路径。
- 面板只显示本轮检查/准入/过滤/延后数量；“本轮未检查”不能被写成“链上没有机会”。

## 不变边界

- 不降低最低净利润、Gas 缓冲、失败 Gas 熔断、余额、nonce、最终模拟或回执门槛；
- 不发送用于“试试”的亏损交易，不用历史价差替代当前精确报价；
- 不把运行、发现、毛利、模拟或竞争者成交记为我方利润；
- 只有成功 receipt、`Executed` 事件、结算余额差和 canonical Gas 一致时才进入经营收益。

## 发布验收

1. 全量格式、lint、类型、构建、单元测试、四套合约测试和秘密扫描通过；
2. GitHub `quality` 对不可变提交通过；
3. 生产先撤销 v10 并确认无未决 mutation、latest/pending nonce 一致；
4. 安装 v0.16.0 后，Linux systemd、Universal runtime hash 和现有执行器地址读回一致；
5. 生成唯一 v11 until-revoked 授权并启动一个 watcher；
6. 状态中能看到动态准入策略、事件/恢复范围、资金检查数、准入数、路线数、Feed 与 RPC 预算；
7. 有且仅有实时全成本正收益时允许签名。没有新回执时明确报告零笔新成交，而不是宣称零机会。
