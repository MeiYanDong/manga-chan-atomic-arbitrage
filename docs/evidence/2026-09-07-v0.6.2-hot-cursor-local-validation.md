# v0.6.2 hot-cursor backlog local validation

- Date: 2026-09-07
- Scope: event-wake scheduling, deterministic regression coverage and repository gates
- Production status: not yet promoted; Linux artifact and board-only canary remain required

## Reproduced production defect

The v0.6.1 production board was healthy and continued reducing its quote backlog, but did not poll another hot-log
range. At `2026-09-07T12:25:44Z`, the read-only event endpoint reported:

- `polls = 1`;
- `lastPollAt = 2026-09-07T11:56:41.143Z`;
- `pendingCandidates = 139`, down from an earlier 171;
- `consecutiveErrors = 0` and `lastError = null`.

This isolates the failure to scheduler ordering rather than a provider error: the nonempty queue returned before
`pollHotEvents` could run.

## Correction and result assertions

The event wait now invokes one existing bounded hot poll before considering the pending queue. It retains the configured
log-range and candidate limits. Four new deterministic tests prove business results rather than source-text order:

1. a newer event is coalesced into an already-pending candidate before it is selected;
2. a wake already selected by the poll is used without a second queue drain;
3. a failed public-RPC poll remains observable while an existing wake still progresses;
4. a queue replaced by reorg handling cannot leak a stale pre-reorg wake.

The focused event suite passed 17 of 17 tests.

## Repository gates

`npm run check` passed locally and covered formatting, JavaScript/Solidity/shell lint, checked-JavaScript type checking,
the production UI build, compile verification, 127 of 127 Node tests, both deterministic Cancun contract suites and a
146-file secret scan. The macOS host does not provide `systemd-analyze`, so the check explicitly skipped that Linux-only
subcheck; the release installer must execute it on Linux before promotion. `npm audit --audit-level=high` reported zero
vulnerabilities.

No executor contract, signing policy, arm, key, transaction or wallet state was changed or accessed by this local
validation. Production acceptance still requires consecutive `lastPollAt` and cursor movement while the pending queue
is nonzero, cgroup stability and signer/wallet non-mutation readback.
